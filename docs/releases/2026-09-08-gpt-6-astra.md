# GPT-6 Astra support

Codex SDK/CLI are pinned together at 0.153.4. Existing business defaults and sandbox policies are preserved; Astra is an optional model.

- Frontend/backend fallback catalogs include Astra (low through ultra, default low, 1,050,000 context tokens), matching the bundled Codex model catalog.
- Usage parsing accepts new and legacy cache-write names. Explicit zero is preserved so accurate telemetry does not fall back to an upper-bound estimate.
- The migration adds a global Astra Standard cost profile without overwriting existing custom prices. USD per 1M tokens: input 10, cached input 1, cache write 12.5, output 50. Above 272,000 input tokens, input/cache rates double and output is multiplied by 1.5. Internal multiplier inherits the active global Sol profile, or 1 when absent. Source: https://developers.openai.com/api/docs/pricing (2026-09-08).

Production rollout:

1. Retain database, environment and Codex Home recovery data plus the previous revision/binary.
2. Set production `CODEX_APP_SERVER_BINARY` to `/usr/local/agent-studio/agent-api/node_modules/.bin/codex`; a legacy global override otherwise bypasses the pinned dependency.
3. Commit/push before running `scripts/deploy-agent-studio.sh`. Keep deployment drain enabled.
4. Verify admin/chat health, deployed revision, actual runtime binary version and Linux workspace/network boundaries.
5. Run an isolated real-account Astra task with local tools, restart/resume its runtime, and verify UsageRecorder events and daily rollups.
6. Add `gpt-6-astra` to the internal employee assistant Run Profile's allowed models, retaining its existing default. Expand to other profiles after channel-specific acceptance.

No permission-profile migration or asynchronous-question UI is included. Existing unsupported interactions remain rejected. Production rollback must consider Codex Home persistence, not only the npm version; the migration leaves existing model profiles unchanged.
