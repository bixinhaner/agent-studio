# 运营触达设计规格

## 目标

把现有“广播管理”升级为“运营触达”工作台，让管理员可以用同一个入口配置邮件、站内信和钉钉触达，控制发送范围，正式发送前用完全一致的链路测试效果，并在发送后追踪结果。

## 产品边界

- 后台菜单路由保持 `#admin/broadcasts`，菜单名改为“运营触达”。
- 后端 API 保持 `/api/admin/broadcasts` 体系，扩展字段与动作，不新建割裂的 marketing 系统。
- 旧广播草稿和已发布记录继续可读；没有新字段的旧记录按站内信广播处理。
- 用户收到的 HTML 邮件使用 portal/runtime branding，不使用 admin console 蓝灰主题。

## 核心流程

1. 管理员在“运营触达”总览查看活动、状态、渠道、预计触达、测试状态和发送结果。
2. 新建或编辑触达活动，配置邮件、站内信、钉钉渠道。
3. 在内容设计中编辑标题、正文、CTA 文案和 URL，并实时预览 portal 品牌 HTML 邮件。
4. 在发送范围中用包含/排除规则选择用户、组织、部门、内外部、角色等受众。
5. 系统实时解析受众，展示预计收件人数、分布和样例收件人。
6. 正式发送前必须成功测试邮件；测试发送复用正式渲染和发送链路，只把投递邮箱替换成管理员测试邮箱。
7. 发布确认页汇总内容、渠道、受众快照、测试状态、退订/不可达排除项和审计信息。
8. 发送后在详情页查看发送结果、失败原因、通知记录和邮件快照。

## 受众规则

受众模型为：

```text
最终收件人 = 包含规则命中的用户 - 排除规则命中的用户 - 不可发送用户
```

MVP 支持：

- `all_users`：全部活跃用户。
- `organization_type`：内部组织或外部客户。
- `organization`：指定组织成员。
- `department`：指定部门成员，可包含子部门。
- `user`：指定用户。
- `role`：指定角色。
- 默认不可发送排除：禁用用户、无邮箱用户、邮件退订用户。

## 邮件与品牌

- 邮件模板从已发布系统设置中读取 `platformName`、`assistantName`、`logoUrl`、`iconUrl`。
- 邮件 CTA 默认跳转 `APP_BASE_URL`，生产可配置为 `https://bailey.baicells.com`。
- 邮件主色使用 portal 品牌的运行时视觉，不跟随 admin console。
- 管理员预览和测试发送必须使用同一 HTML renderer。
- 测试邮件正文和正式邮件正文完全一致，不出现“测试”字样。

## 数据与审计

- `broadcast_messages` 扩展为触达活动主表，保留旧字段。
- `broadcast_targets` 保留旧广播目标兼容；新受众规则存在主表 JSON 字段中。
- `notification_records` 记录测试邮件、正式邮件和钉钉发送结果。
- 站内信继续写入 `inbox_items`。
- 发布时保存受众快照，后续组织/部门变更不影响已发送记录复盘。

## 错误处理

- 没有发送渠道时不允许保存为可发布状态。
- 邮件渠道启用但没有可达邮箱时，发送范围页显示阻断提示。
- 正式发送前没有成功测试，发布按钮禁用。
- 内容或受众在测试后变更，测试状态回到“需重新测试”。
- SMTP 未配置时保留 debug 模式结果，但前端明确展示“未真实投递”。

## 验证

- 后端测试覆盖受众解析、测试发送、发布前测试校验、邮件 HTML 品牌渲染。
- 前端构建验证触达工作台类型和交互无编译错误。
